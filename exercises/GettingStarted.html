About GnuCOBOL

The compiler we use for this course is GnuCOBOL, a free, open-source COBOL compiler. Unlike a graphical IDE, GnuCOBOL is a command-line tool: you write your program in any text editor, then use the cobc compiler in a terminal to turn the source into a native program you can run.

The whole workflow is three steps — edit the source, compile it with cobc, then run the program. In this exercise you will install GnuCOBOL, then compile and run your first COBOL program.

Getting the program

We will start with an existing COBOL program. Download GettingStarted.cbl and save it to a working folder you can find again — for example a cobol folder in your home directory. The full source is shown below.

Download GettingStarted.cbl 
       >>SOURCE FORMAT IS FREE
IDENTIFICATION DIVISION.
PROGRAM-ID.  GettingStarted.
AUTHOR.  Michael Coughlan.
*> This program should accept two numbers from the user, multiply them together
*> and then display the result.  Unfortunately it does not work correctly.
*> Re-write the program so that it prompts the user for input and displays
*> the correct result.


DATA DIVISION.

WORKING-STORAGE SECTION.
01  Num1                                PIC 9  VALUE ZEROS.
01  Num2                                PIC 9  VALUE ZEROS.
01  Result                              PIC 99 VALUE ZEROS.

PROCEDURE DIVISION.
Calc-Result.
    ACCEPT Num1.
    MULTIPLY Num1 BY Num2 GIVING Result.
    ACCEPT Num2.
    DISPLAY "Result is = ", Result.
    STOP RUN.

This program is meant to accept two numbers, multiply them, and display the result — but it has a couple of bugs. You will fix them later in the exercise.

Compiling the program

Open a terminal and change into the folder where you saved the file. Compile it with the -x flag, which tells cobc to build a standalone executable program (rather than a callable module):

On success cobc prints nothing and writes an executable next to the source: gettingstarted on Linux and macOS, or gettingstarted.exe on Windows.

This source begins with the >>SOURCE FORMAT IS FREE directive, so cobc already knows to read it as free-format COBOL. If you write a program without that directive and use free-format layout, pass the -free flag as well: cobc -x -free yourprogram.cbl.

Notice two problems. First, the program never tells you what to type — it just waits silently for input, so you have to know to enter the two numbers. Second, the answer is wrong: entering 3 and 5 should give 15, but it prints 00. That is because the MULTIPLY runs before the second number is accepted, so it multiplies by zero.

The edit–compile–run loop

This is the loop you will repeat throughout the course:

  1. Edit the .cbl source in your text editor and save it.
  2. Recompile it: cobc -x gettingstarted.cbl.
  3. Run the program again and check the result.

There is no IDE to configure and no debugger to start — just your editor, the compiler, and the terminal.

Fixing the program

Change the program so that it prompts the user before each input and produces the correct answer. To print a prompt and leave the cursor on the same line so the user can type beside it, use DISPLAY with the WITH NO ADVANCING phrase, for example:

DISPLAY "Enter the first number: " WITH NO ADVANCING

You will also need to move the MULTIPLY so that it runs only after both numbers have been accepted. After each change, recompile and rerun to confirm the fix.

Conclusion

See if you can replace the MULTIPLY statement with the equivalent COMPUTE statement.

The format for the COMPUTE is

COMPUTE result = operand operator operand
